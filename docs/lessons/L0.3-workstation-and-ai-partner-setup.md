## Step 4: Python with uv, and your first Python script

### 4.1 Concepts: how Python projects work, compared with .NET

Python, like C#, needs a runtime (the **interpreter**) and packages. The big difference is **where packages live**:

- In .NET, each project lists packages in its `.csproj`, and NuGet keeps them in a shared cache. Two projects can use different versions of the same package with no conflict.
- In Python, packages are installed **into an environment**: a folder with an interpreter and a set of packages. If all your projects shared one global environment, project A needing `numpy 1.x` and project B needing `numpy 2.x` would break each other.
- The fix is a **virtual environment** (`.venv` folder) per project.

**uv** is a modern, very fast tool that manages all of this for you. The course uses it from L2.1, so you'll learn it now:

| .NET | Python with uv |
|---|---|
| .NET SDK versions | `uv python install 3.12` (installs Python itself) |
| `.csproj` | `pyproject.toml` |
| `dotnet add package X` | `uv add X` |
| NuGet / nuget.org | pip / PyPI (pypi.org) |
| `packages.lock.json` | `uv.lock` |
| `bin/` and `obj/` | `.venv/` (never committed) |
| `dotnet run` | `uv run script.py` |

**Why Python 3.12?** It's recent but mature, and the research libraries we'll use later (PyTorch, escnn, timm) all support it. The very newest Python versions sometimes lack packages for a few months.

### 4.4 Your first script: the WSI size calculator

Create `wsi_math.py` in `sandbox/l03-python/`. It redoes the L0.1 gigapixel calculation in code:

```python
"""Whole-slide image size calculator (Lesson L0.3, step 4)."""

BYTES_PER_PIXEL = 3  # one byte each for red, green and blue


def pixels_from_mm(size_mm: float, mpp: float) -> int:
    """Convert a physical length in millimetres to level-0 pixels."""
    microns = size_mm * 1000
    return round(microns / mpp)


def describe_slide(name: str, width_mm: float, height_mm: float, mpp: float) -> dict:
    """Return the pixel size and memory size of a slide as a dictionary."""
    width_px = pixels_from_mm(width_mm, mpp)
    height_px = pixels_from_mm(height_mm, mpp)
    pixels = width_px * height_px
    return {
        "name": name,
        "width_px": width_px,
        "height_px": height_px,
        "gigapixels": pixels / 1e9,
        "uncompressed_gb": pixels * BYTES_PER_PIXEL / 1e9,
    }


def main() -> None:
    slides = [
        ("Typical 40x slide", 20, 15, 0.25),
        ("Same tissue at 20x", 20, 15, 0.5),
        ("L0.1 exercise", 25, 18, 0.5),
    ]

    for name, width_mm, height_mm, mpp in slides:
        info = describe_slide(name, width_mm, height_mm, mpp)
        print(
            f"{info['name']:<20}"
            f"{info['width_px']:>8,} x {info['height_px']:>7,} px"
            f"  = {info['gigapixels']:5.2f} gigapixels"
            f"  = {info['uncompressed_gb']:6.2f} GB uncompressed"
        )


if __name__ == "__main__":
    main()
```

Run it:

```bash
uv run wsi_math.py
```

Expected output:

```
Typical 40x slide     80,000 x  60,000 px  =  4.80 gigapixels  =  14.40 GB uncompressed
Same tissue at 20x    40,000 x  30,000 px  =  1.20 gigapixels  =   3.60 GB uncompressed
L0.1 exercise         50,000 x  36,000 px  =  1.80 gigapixels  =   5.40 GB uncompressed
```

The first `uv run` creates `.venv/` automatically. You never "activate" anything by hand.

### 4.5 Reading the code as a C# developer

| In the script | What it means | C# equivalent |
|---|---|---|
| `"""..."""` at the top of a file or function | A **docstring**: documentation for that file or function | `/// <summary>` XML comments |
| `BYTES_PER_PIXEL = 3` | A module-level constant. Python has no `const`; UPPER_CASE is the convention that says "don't change this" | `const int BytesPerPixel = 3;` |
| `def pixels_from_mm(size_mm: float, mpp: float) -> int:` | A function. `: float` and `-> int` are **type hints** | `static int PixelsFromMm(double sizeMm, double mpp)` |
| Indentation (4 spaces) | **Indentation is the syntax.** Blocks are defined by indenting, not by `{ }`. Wrong indentation is a real error | `{ ... }` |
| `round(microns / mpp)` | `/` always gives a float in Python (`7 / 2 == 3.5`). `//` is integer division | `(int)Math.Round(microns / mpp)` |
| `{ "name": name, ... }` | A **dict**: key-value pairs | `Dictionary<string, object>` |
| `[ (...), (...) ]` | A **list** of **tuples** | `List<(string, double, double, double)>` |
| `for name, width_mm, height_mm, mpp in slides:` | Loop with tuple **unpacking**: each tuple is split into four variables | `foreach (var (name, w, h, mpp) in slides)` |
| `f"{x:>8,}"` | An **f-string** with a format spec: right-align in 8 characters, thousands separator | `$"{x,8:N0}"` |
| `if __name__ == "__main__": main()` | Runs `main()` only when the file is run directly, not when another file imports it | `static void Main()` |
| `snake_case` names | Python naming convention for functions and variables (PEP 8) | `PascalCase` methods, `camelCase` locals |

One important difference: **type hints are not enforced when the code runs.** Python would let you call `pixels_from_mm("twenty", 0.25)` and fail only at the division. Tools in your editor (Pylance) and later in CI check the hints for you, like the C# compiler does, but only if you use them. In this course we always write type hints.

**Try it:** add a fourth slide to the list, a CAMELYON16 slide of about 22 × 10 mm at 0.243 mpp, and run again.

**Done when:** `uv run wsi_math.py` prints four lines and you can explain every line of the script to yourself.

## Step 5: Read your L0.1 slide from Python

Now the same thing for a real file. We use **OpenSlide**, the library from L0.1 that reads many slide formats through one API.

### 5.1 Add the packages

```bash
uv add openslide-python openslide-bin
```

- `openslide-python` is the Python API.
- `openslide-bin` contains the native OpenSlide library (the C code that actually decodes slide files), so you don't have to install it separately. **.NET analogy:** a NuGet package that ships native `.dll` files inside `runtimes/`, like SkiaSharp does.

Look at `pyproject.toml` again: both packages are now under `dependencies`, and `uv.lock` records exact versions.

### 5.2 The script

Create `inspect_slide.py`:

```python
"""Print the key properties of a whole-slide image and save a thumbnail (Lesson L0.3, step 5).

Usage:
    uv run inspect_slide.py <path-to-slide>
"""

import sys
from pathlib import Path

import openslide


def read_mpp(slide: openslide.OpenSlide) -> float | None:
    """Return microns per pixel, or None if the file doesn't say."""
    value = slide.properties.get(openslide.PROPERTY_NAME_MPP_X)
    return float(value) if value is not None else None


def describe(path: Path) -> None:
    with openslide.OpenSlide(str(path)) as slide:
        width, height = slide.dimensions
        mpp = read_mpp(slide)
        vendor = slide.properties.get(openslide.PROPERTY_NAME_VENDOR, "unknown")
        objective = slide.properties.get(openslide.PROPERTY_NAME_OBJECTIVE_POWER, "unknown")

        print(f"File:            {path.name}")
        print(f"Size on disk:    {path.stat().st_size / 1e6:,.1f} MB")
        print(f"Vendor:          {vendor}")
        print(f"Level 0 size:    {width:,} x {height:,} px")
        print(f"Objective power: {objective}")

        if mpp is None:
            print("mpp:             not stored in this file")
        else:
            print(f"mpp:             {mpp:.4f} µm/pixel")
            print(f"Physical size:   {width * mpp / 1000:.1f} x {height * mpp / 1000:.1f} mm")

        uncompressed_gb = width * height * 3 / 1e9
        print(f"Uncompressed:    {uncompressed_gb:,.1f} GB")

        print(f"Pyramid levels:  {slide.level_count}")
        for level in range(slide.level_count):
            level_width, level_height = slide.level_dimensions[level]
            downsample = slide.level_downsamples[level]
            print(f"  level {level}: {level_width:>8,} x {level_height:>8,} px   downsample {downsample:6.2f}")

        names = list(slide.associated_images.keys())
        print(f"Associated images: {', '.join(names) if names else 'none'}")

        thumbnail = slide.get_thumbnail((1024, 1024))
        thumbnail_path = path.with_name(f"{path.stem}_thumbnail.png")
        thumbnail.save(thumbnail_path)
        print(f"Thumbnail saved: {thumbnail_path}")


def main() -> None:
    if len(sys.argv) != 2:
        print("Usage: uv run inspect_slide.py <path-to-slide>")
        sys.exit(1)

    path = Path(sys.argv[1])
    if not path.exists():
        print(f"File not found: {path}")
        sys.exit(1)

    describe(path)


if __name__ == "__main__":
    main()
```

Run it on your TCGA slide from L0.1 (use your real file name; on Windows, `\` works in paths too):

```bash
uv run inspect_slide.py ../../data/raw/TCGA-XX-XXXX-01Z-00-DX1.<id>.svs
```

You'll see something like this (your numbers will differ):

```
File:            TCGA-....svs
Size on disk:    312.4 MB
Vendor:          aperio
Level 0 size:    95,615 x 74,462 px
Objective power: 40
mpp:             0.2520 µm/pixel
Physical size:   24.1 x 18.8 mm
Uncompressed:    21.4 GB
Pyramid levels:  4
  level 0:   95,615 x   74,462 px   downsample   1.00
  level 1:   23,903 x   18,615 px   downsample   4.00
  level 2:    5,975 x    4,653 px   downsample  16.00
  level 3:    2,987 x    2,326 px   downsample  32.01
Associated images: label, macro, thumbnail
Thumbnail saved: ../../data/raw/TCGA-..._thumbnail.png
```

Open the thumbnail. The thumbnail is saved next to the slide in `data/raw/`, which Git ignores.

### 5.3 What's new in this script

| Code | Meaning |
|---|---|
| `import sys`, `from pathlib import Path` | Imports from Python's standard library. `Path` is like `FileInfo`/`Path` in .NET |
| `with openslide.OpenSlide(...) as slide:` | A **context manager**: the slide file is closed automatically when the block ends, even on error. Same idea as C#'s `using var slide = ...;` |
| `slide.properties.get(key, default)` | Read a property; return `default` (or `None`) if missing, instead of throwing. Like `TryGetValue` |
| `float \| None` | "A float or nothing", like `double?` |
| `float(value) if value is not None else None` | Conditional expression, like `value != null ? double.Parse(value) : null` |
| `width, height = slide.dimensions` | Tuple unpacking again |
| `range(slide.level_count)` | The numbers 0, 1, …, count−1, like `Enumerable.Range(0, count)` |
| `sys.argv` | Command-line arguments; `sys.argv[0]` is the script name, so the first real argument is `sys.argv[1]` |
| `sys.exit(1)` | Exit with an error code, like `return 1;` from `Main` |

Notice that `get_thumbnail` never loads the whole slide: OpenSlide reads a small pyramid level and resizes it. This is exactly the "only read what you need" idea from L0.1.

**Compare with QuPath:** check that width, height, mpp and downsamples match your L0.1 properties table. Run it on your second slide too. If the CAMELYON16 slide shows "mpp: not stored in this file", that's a real lesson: **not every file carries its mpp**, and the platform will need a fallback (L3.3).

**Done when:** the script prints the properties of both slides and they match your QuPath notes.

## Step 6: Docker

### 6.1 Concepts

**Docker** runs software in **containers**: isolated packages with an app and everything it needs (libraries, runtime, configuration). From L2.2 you'll run PostgreSQL, MinIO, RabbitMQ and Grafana in containers instead of installing them on your PC.

| Term | Meaning | .NET analogy |
|---|---|---|
| **Image** | A read-only template: the app and its files | A compiled, published app (or a class) |
| **Container** | A running instance of an image | A running process (or an object created from the class) |
| **Registry** | Where images are stored and downloaded (Docker Hub) | NuGet.org, for images |
| **Volume** | Storage that survives when a container is deleted | A database file kept outside the app folder |
| **Docker Compose** | A YAML file that starts several containers together | A solution that starts several projects at once |

A container is **not** a virtual machine: it shares the host's Linux kernel (on Windows, the WSL2 kernel), so it starts in about a second and uses little memory.

### 6.2 Install

1. Install **Docker Desktop** from <https://www.docker.com/products/docker-desktop>. It's free for personal use, education and small businesses.
2. During setup on Windows, keep **"Use WSL 2 based engine"** selected.
3. Start Docker Desktop and wait until it says the engine is running.

Test it:

```bash
docker run --rm hello-world
```

You should see "Hello from Docker!". What happened: Docker downloaded the `hello-world` image from Docker Hub, created a container, ran it, printed its output, and `--rm` deleted the container afterwards.

**Done when:** `hello-world` prints its message.

## Step 8: A C# toolchain checker

Now a small C# program, in the language you know, that checks every tool in one command. You'll re-run it whenever you set up a new machine.

From `pathology-platform/`:

```bash
mkdir tools
dotnet new console -n ToolCheck -o tools/ToolCheck
```

Replace `tools/ToolCheck/Program.cs` with:

```csharp
using System.Diagnostics;

// Each check: a display name, the command to run, and its arguments.
var checks = new List<ToolCheck>
{
    new("Git", "git", "--version"),
    new(".NET SDK", "dotnet", "--version"),
    new("uv", "uv", "--version"),
    new("Python 3.12 (managed by uv)", "uv", "run --no-project --python 3.12 python --version"),
    new("Docker CLI", "docker", "--version"),
    new("Docker engine running", "docker", "info --format \"{{.ServerVersion}}\""),
    new("VS Code", "code", "--version"),
};

Console.WriteLine("Pathology platform toolchain check");
Console.WriteLine(new string('-', 70));

var failures = 0;
foreach (var check in checks)
{
    var result = Run(check.Command, check.Arguments);
    var status = result.Success ? "[ OK ]" : "[FAIL]";
    if (!result.Success)
    {
        failures++;
    }

    Console.WriteLine($"{status} {check.Name,-30} {result.FirstLine}");
}

Console.WriteLine(new string('-', 70));
Console.WriteLine(failures == 0 ? "All tools found." : $"{failures} check(s) failed.");
return failures == 0 ? 0 : 1;

static RunResult Run(string command, string arguments)
{
    // On Windows some tools (like VS Code's 'code') are .cmd scripts, which
    // Process.Start can't launch directly, so we run them through cmd.exe.
    var startInfo = OperatingSystem.IsWindows()
        ? new ProcessStartInfo("cmd.exe", $"/c {command} {arguments}")
        : new ProcessStartInfo(command, arguments);
    startInfo.RedirectStandardOutput = true;
    startInfo.RedirectStandardError = true;
    startInfo.UseShellExecute = false;

    try
    {
        using var process = Process.Start(startInfo)!;

        // Read both streams at the same time so neither can fill up and block the process.
        var outputTask = process.StandardOutput.ReadToEndAsync();
        var errorTask = process.StandardError.ReadToEndAsync();
        process.WaitForExit();

        var text = string.IsNullOrWhiteSpace(outputTask.Result) ? errorTask.Result : outputTask.Result;
        var firstLine = text
            .Split('\n', StringSplitOptions.RemoveEmptyEntries)
            .Select(line => line.Trim())
            .FirstOrDefault() ?? "";

        return new RunResult(process.ExitCode == 0, firstLine);
    }
    catch (System.ComponentModel.Win32Exception)
    {
        // Thrown on macOS/Linux when the command isn't on the PATH.
        return new RunResult(false, "not found on PATH");
    }
}

record ToolCheck(string Name, string Command, string Arguments);

record RunResult(bool Success, string FirstLine);
```

Run it:

```bash
dotnet run --project tools/ToolCheck
```

Expected (versions will differ):

```
Pathology platform toolchain check
----------------------------------------------------------------------
[ OK ] Git                            git version 2.x
[ OK ] .NET SDK                       10.0.x
[ OK ] uv                             uv 0.x
[ OK ] Python 3.12 (managed by uv)    Python 3.12.x
[ OK ] Docker CLI                     Docker version 2x.x
[ OK ] Docker engine running          2x.x
[ OK ] VS Code                        1.x
----------------------------------------------------------------------
All tools found.
```

If "Docker engine running" fails, Docker Desktop isn't started. Start it and run again.

Things worth noticing, even though you know C#:

- **Top-level statements** with a `return` value give the process an exit code. CI pipelines (L2.3) use exit codes to decide pass or fail, so this tool could run in CI later.
- **Records** (`ToolCheck`, `RunResult`) are small immutable data types, the C# cousin of Python's tuples and dataclasses.
- Reading stdout and stderr **concurrently** avoids a classic deadlock when a child process writes a lot to one stream.

**Done when:** every line shows `[ OK ]`.

## Step 9: The AI context prompt

### 9.1 Why

An AI partner gives much better answers when it knows your project, your level and your rules. Instead of re-explaining every time, you keep one file, `docs/ai-context.md`, and paste it at the start of any new AI conversation (or attach it). It also documents your project for humans.

In **this** Claude project, the context is already stored, so you don't need to paste it here. Use the file when you work in another chat or tool, and keep it updated as decisions are made. If you later use Claude Code inside your repository, the same content can go in a `CLAUDE.md` file at the repository root, which Claude Code reads automatically.

### 10.2 Check yourself

1. Why does each Python project get its own `.venv`, when .NET projects don't need anything similar?
2. What does `uv run` do the first time you run it in a project?
3. Are Python type hints checked when the program runs?
4. What's the difference between a Docker image and a container?
5. Why do we pass `--vcs none` to `uv init` here?
6. Why choose .NET 10 rather than .NET 8 today?

<details>
<summary>Answers</summary>

1. Python installs packages into an environment, so projects sharing one would conflict on versions. NuGet resolves versions per project from a shared cache, so .NET doesn't have this problem.
2. It creates `.venv` with the pinned Python version, installs the dependencies from `pyproject.toml`/`uv.lock`, then runs the script in that environment.
3. No. They're checked by tools (Pylance in the editor, type checkers in CI), not by the interpreter.
4. An image is a read-only template; a container is a running (or stopped) instance created from it.
5. `pathology-platform/` is already a Git repository; uv would otherwise create a nested repository inside it.
6. .NET 10 is the current LTS (supported to November 2028); .NET 8 support ends in November 2026.

</details>
